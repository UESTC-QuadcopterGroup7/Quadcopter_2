# MPU6050 与 HMC5883L：参数、单位和项目配置

本文结合当前项目解释传感器数据的含义，重点回答：

- `g`、`G`、Gauss、LSB、量程和灵敏度分别是什么？
- 手机收到的 `MPU A:... G:...`、`HMC M:...` 如何换算？
- 为什么加速度 Z 轴校准要保留 1g？
- 初始化配置、读取频率、发送频率有什么区别？

本文描述的是编写时核对的源码，不代表已经测得芯片实际配置。硬件型号、寄存器读回值和测量环境仍需验证。本次只新增文档，不修改程序。

## 1. 先区分三个传感器

| 器件 | 测量对象 | 三轴数据 | 常用物理单位 | 不能直接得到什么 |
|---|---|---|---|---|
| MPU6050 加速度计 | 比力，即非重力作用导致的单位质量受力 | AX、AY、AZ | g、m/s² | 不能直接得到速度和位置 |
| MPU6050 陀螺仪 | 绕各轴的转动速度 | GX、GY、GZ | °/s、rad/s | 不能直接得到角度 |
| HMC5883L 磁力计 | 各轴方向的磁场分量 | MX、MY、MZ | Gauss、µT | 不能直接把某一轴当成航向角 |

“MPU6050 六轴”指三个加速度轴和三个陀螺仪轴，并不是六个角度。

GY-86 是模块名称；MPU6050、HMC5883L、MS5611 是其中可能搭载的具体芯片。本项目已暂停 MS5611 气压计，不在本文展开。

```mermaid
flowchart LR
    A[运动和环境磁场] --> B[传感器检测与内部处理]
    B --> C[输出寄存器中的整数计数]
    C --> D[STM32 读取]
    D --> E[校准补偿]
    E --> F[按量程换算物理单位]
    F --> G[姿态或航向计算]
    E --> H[当前项目直接发送整数计数]
```

**当前项目的串口输出仍是原始整数计数，没有把 MPU 和 HMC 的读数换算成物理单位后上报。
姿态解算已由 `MyLib/Attitude.c` 实现（见 [四元数姿态解算](../Attitude_Quaternion.md)），
但它只在内部完成量程换算并输出角度，不改变这条原始计数的上报路径。**

## 2. g、G、LSB 和原始值

### 2.1 小写 g：重力加速度单位

这里的 `g` 不是克，而是以标准重力加速度为参考的单位：

```text
1g = 9.80665 m/s²
0.5g = 4.903325 m/s²
```

标准重力用于单位换算；真实当地重力随位置、海拔等略有变化。

加速度计不是简单的“运动加速度显示器”。它测量比力，可写成：

```text
比力 = 运动加速度 - 重力加速度向量
```

桌面支撑使静止的传感器测到约 1g；自由落体时理想读数接近 0g。因此，“不动时三个轴都应该为零”是错误的。

水平静止、传感器 +Z 朝上，理想输出为：

```text
AX ≈ 0g
AY ≈ 0g
AZ ≈ +1g
```

如果翻转为 +Z 朝下，AZ 应接近 -1g。倾斜时重力投影分布到多个轴，静止时三个轴的向量模长仍应约为 1g。

### 2.2 大写 G 或 Gauss：磁场单位

磁场中的 `G` 表示 Gauss，与加速度的 `g` 完全不同：

```text
1 G = 1 Gauss = 10^-4 T = 100 µT
1 µT = 0.01 G
```

地球表面磁场总强度通常约为 25～65 µT，即 0.25～0.65 Gauss，具体取决于地点。

另外，手机字符串 `MPU ... G:...` 中的 `G:` 是本程序给 **Gyro（陀螺仪）** 取的标签，不代表这些数值的单位是 Gauss。

### 2.3 LSB：最低有效位与计数步长

LSB 是 Least Significant Bit，原意为最低有效位。在传感器灵敏度描述中，可把它理解为整数输出的一个计数：

```text
原始值从 100 增加到 101：增加 1 LSB
```

`2048 LSB/g` 表示输入变化 1g 时，输出计数约变化 2048。

**LSB 不是固定的物理单位。** 同样是 1 LSB：

- MPU 加速度计中可以对应若干 g；
- MPU 陀螺仪中可以对应若干 °/s；
- HMC 磁力计中可以对应若干 Gauss。

换算必须知道传感器种类和当前量程。

### 2.4 有符号整数、分辨率和精度

MPU6050 每轴输出使用两个字节，组成 16 位有符号二进制补码：

```text
0x0000 = 0
0x0001 = 1
0x7FFF = 32767
0x8000 = -32768
0xFFFF = -1
```

负数本身不表示故障；它通常表示沿负轴方向。只有结合“不合理的数值、所有轴同时异常、无应答”等证据，才能判断通信失败。

HMC5883L 同样使用两个字节表达每轴有符号数据，但其 ADC 和有效输出范围不能当成 MPU6050 的完整 16 位量程来换算，应使用 HMC 的增益表。

区分三个概念：

| 概念 | 含义 | 例子 |
|---|---|---|
| 分辨率 | 最小数字计数步长对应的物理量 | ±16g 时约 0.000488g/LSB |
| 精度 | 结果与真实值的接近程度 | 受偏置、比例误差、温度等影响 |
| 噪声 | 同一输入下读数的随机变化 | 静止时读数仍有小幅波动 |

**16 位输出不等于 16 位有效精度；一个计数的步长也不等于测量误差。**

## 3. 量程、灵敏度与换算系数

量程表示可以测量的输入范围。例如 ±16g 可以测量正负方向的加速度，比 ±2g 更不容易在大运动时饱和。

灵敏度表示单位输入对应多少计数，如 `2048 LSB/g`。

同一器件扩大满量程，通常会降低数字灵敏度：

```text
更大量程 → 每单位物理量对应更少计数 → 计数步长更粗
```

换算关系为：

```text
物理量 = 校准后的计数 / 灵敏度
换算系数 = 1 / 灵敏度
```

量程应覆盖实际运动，并留出余量，而不是一律选最大值或最小值。饱和后数据被截在边界，软件不能恢复超出量程的真实输入。

## 4. MPU6050 加速度计

### 4.1 四档量程

`ACCEL_CONFIG` 的 `AFS_SEL` 位位于 bit[4:3]：

| AFS_SEL | 无其他附加位时的配置值 | 量程 | 标称灵敏度 | 1g 计数 | g/LSB |
|---|---|---|---:|---:|---:|
| 0 | 0x00 | ±2g | 16384 LSB/g | 16384 | 0.0000610352 |
| 1 | 0x08 | ±4g | 8192 LSB/g | 8192 | 0.0001220703 |
| 2 | 0x10 | ±8g | 4096 LSB/g | 4096 | 0.0002441406 |
| 3 | 0x18 | ±16g | 2048 LSB/g | 2048 | 0.0004882813 |

当前 `MyLib/GY86.h`：

```c
#define MPU6050_ACCEL_CONFIG_VALUE 0x18u
#define MPU6050_ACCEL_1G_RAW \
    (16384 >> ((MPU6050_ACCEL_CONFIG_VALUE >> 3) & 0x03u))
```

因此当前是 **±16g、2048 LSB/g**。宏根据配置位计算 1g 计数，避免把 8192 固定写死。

### 4.2 原始值如何换算

当前量程下：

```c
float ax_g = calibrated_ax / 2048.0f;
float ax_m_s2 = ax_g * 9.80665f;
```

示例：

| 校准后计数 | 加速度 |
|---:|---|
| 0 | 0g |
| 1024 | +0.5g |
| 2048 | +1g |
| -2048 | -1g |

### 4.3 为什么 Z 轴校准要减 1g

单姿态校准假设：**水平静止，+Z 朝上**。

```text
X 偏置 = AX 平均值
Y 偏置 = AY 平均值
Z 偏置 = AZ 平均值 - 1g 对应的计数

补偿值 = 原始值 - 对应偏置
```

例如当前 ±16g，AZ 平均值为 1994：

```text
Z 偏置 = 1994 - 2048 = -54
静止补偿结果 = 1994 - (-54) = 2048
```

这是去掉传感器偏置，同时保留真实重力。

**只有 ±4g 档位才减 8192；当前 ±16g 应减 2048。**

“去零偏”和“去重力”不是同一件事。若要得到运动加速度，需要根据姿态估计重力在三个轴上的投影，再做向量补偿，不能在任何姿态下始终只给 Z 减去 1g。

该单姿态方法不能完整估计比例误差、轴不正交误差；更完善的加速度校准可使用六面静置法。

## 5. MPU6050 陀螺仪

### 5.1 四档量程

`GYRO_CONFIG` 的 `FS_SEL` 位位于 bit[4:3]：

| FS_SEL | 无其他附加位时的配置值 | 量程 | 数据手册标称灵敏度 |
|---|---|---|---:|
| 0 | 0x00 | ±250 °/s | 131 LSB/(°/s) |
| 1 | 0x08 | ±500 °/s | 65.5 LSB/(°/s) |
| 2 | 0x10 | ±1000 °/s | 32.8 LSB/(°/s) |
| 3 | 0x18 | ±2000 °/s | 16.4 LSB/(°/s) |

当前初始化写入 `GYRO_CONFIG = 0x18`，因此是 **±2000 °/s**。

### 5.2 °/s、rad/s 和角度

```text
180° = π rad
1 °/s = π / 180 rad/s
```

按当前标称灵敏度换算：

```c
float gx_deg_s = calibrated_gx / 16.4f;
float gx_rad_s = gx_deg_s * 0.01745329252f;
```

例如 164 LSB 对应约 10 °/s，而不是 10°。

对单轴、短时间且条件合适的情况，角度增量可近似为：

```text
角度增量 = 角速度 × 实际经过的时间
```

三维姿态解算需要处理坐标变换和旋转耦合，不能把三轴陀螺仪始终简单积分成三个独立欧拉角。

### 5.3 RAW_TO_ANGLE 与 RAW_TO_RAD

参考代码中的：

```c
#define RAW_TO_ANGLE 0.0610351f
#define RAW_TO_RAD   0.0010653f
```

对应的是按理想满量程近似计算：

```text
2000 / 32768 ≈ 0.06103515625 (°/s)/LSB
上述系数 × π / 180 ≈ 0.0010652644 (rad/s)/LSB
```

数据手册标称的 16.4 LSB/(°/s) 对应 `1/16.4 ≈ 0.06097561`。两种近似约差 0.1%，应明确采用哪种依据，不要把近似系数当成逐颗芯片的精确校准结果。

`RAW_TO_ANGLE` 名字并不准确：它转换的是**角速度**，不是角度。更清晰的名字是 `GYRO_RAW_TO_DEG_S`。

当前项目尚未定义或使用这两个宏；蓝牙发送的仍是补偿后的整数计数。

### 5.4 陀螺仪零偏为什么重要

静止时真实角速度应约为零，因此三轴平均计数可作为偏置：

```text
陀螺仪偏置 = 静止原始值平均
补偿计数 = 原始计数 - 偏置
```

若还有 0.1 °/s 的残余偏置，单纯积分 60 秒就可能积累约 6° 的误差。偏置还会随温度变化，一次上电校准不能保证所有温度下都没有漂移。

## 6. MPU6050 初始化中的其他参数

当前初始化位于 `MyLib/GY86.c` 的 `MPU6050_Init()`：

| 寄存器 | 当前写入值 | 作用 |
|---|---|---|
| PWR_MGMT_1 | 0x01 | 退出休眠，选择 X 轴陀螺仪参考的 PLL 时钟 |
| PWR_MGMT_2 | 0x00 | 不禁用加速度和陀螺仪各轴 |
| SMPLRT_DIV | 0x09 | 设置采样率分频 |
| CONFIG | 0x02 | 设置数字低通滤波 DLPF |
| GYRO_CONFIG | 0x18 | 陀螺仪 ±2000 °/s |
| ACCEL_CONFIG | 0x18 | 加速度计 ±16g |
| USER_CTRL | 0x00 | 未启用 MPU 内部 I²C 主机等功能 |
| INT_PIN_CFG | 0x02 | 开启 I²C 旁路 |

`DLPF_CFG = 2` 时，标称加速度带宽约 94 Hz、陀螺仪带宽约 98 Hz；相应延迟约为 3.0 ms、2.8 ms。滤波能抑制部分高频噪声，但带来延迟，也不能消除所有振动干扰。

在当前滤波配置下，陀螺仪用于采样率计算的输出基准为 1 kHz：

```text
寄存器采样率 = 1000 / (1 + SMPLRT_DIV)
             = 1000 / (1 + 9)
             = 100 Hz
```

加速度计内部更新机制与陀螺仪不完全相同，不能把所有内部环节都简单描述为“100 Hz”。对应用程序而言，更不能把更快的寄存器读取当成新的独立六轴样本。

旁路配置用于让 STM32 直接访问接在 MPU 辅助总线上的地磁计，具体是否需要取决于模块布线。开启旁路不是地磁计校准。

## 7. HMC5883L 磁力计

### 7.1 当前三个配置寄存器

当前 `HMC5883L_Init()`：

```c
HMC5883L_WriteReg(HMC5883L_CONFIG_A, 0x18);
HMC5883L_WriteReg(HMC5883L_CONFIG_B, 0x20);
HMC5883L_WriteReg(HMC5883L_MODE,     0x00);
```

含义为：

| 配置 | 位字段 | 当前设置 |
|---|---|---|
| CONFIG_A = 0x18 | MA[1:0] = 00 | 每次输出采用 1 个内部样本的平均设置 |
| CONFIG_A = 0x18 | DO[2:0] = 110 | 连续模式输出速率 75 Hz |
| CONFIG_A = 0x18 | MS[1:0] = 00 | 正常测量，不启用正/负偏置自检 |
| CONFIG_B = 0x20 | GN[2:0] = 001 | 推荐磁场范围 ±1.3 Gauss，标称增益 1090 LSB/Gauss |
| MODE = 0x00 | MD[1:0] = 00 | 连续测量模式 |

例如常见配置 `CONFIG_A = 0x70` 才表示 8 样本平均、15 Hz；它不是当前项目的配置。

### 7.2 磁场增益表

| CONFIG_B | 数据手册推荐磁场范围 | 标称增益，LSB/Gauss | 约 µT/LSB |
|---|---|---:|---:|
| 0x00 | ±0.88 Gauss | 1370 | 0.0730 |
| 0x20 | ±1.3 Gauss | 1090 | 0.0917 |
| 0x40 | ±1.9 Gauss | 820 | 0.1220 |
| 0x60 | ±2.5 Gauss | 660 | 0.1515 |
| 0x80 | ±4.0 Gauss | 440 | 0.2273 |
| 0xA0 | ±4.7 Gauss | 390 | 0.2564 |
| 0xC0 | ±5.6 Gauss | 330 | 0.3030 |
| 0xE0 | ±8.1 Gauss | 230 | 0.4348 |

这些是标称换算参数，推荐磁场范围不等于“使用完整 int16_t 数值区间”。不要套用 MPU 的 `满量程/32768` 公式计算 HMC 增益。

当前换算示例：

```c
float mx_gauss = mx_raw / 1090.0f;
float mx_uT = mx_gauss * 100.0f;
```

例如 MX = 545 LSB：

```text
MX = 545 / 1090 = 0.5 Gauss = 50 µT
```

这是 X 轴磁场分量，不是磁场总强度。总强度需计算：

```text
|B| = sqrt(BX² + BY² + BZ²)
```

旋转传感器会改变各轴分量；在磁场稳定、校准良好的环境中，向量模长应大致保持稳定。

### 7.3 数据字节顺序与故障码

HMC5883L 从 0x03 开始的六个数据字节排列是：

```text
X 高字节、X 低字节、
Z 高字节、Z 低字节、
Y 高字节、Y 低字节
```

**是 X、Z、Y，不是 X、Y、Z。** 连续读取后必须按正确顺序解析。

HMC5883L 的典型有效输出范围为 -2048～2047；发生测量溢出时，对应数据寄存器会出现 **-4096，即 0xF000**。

三个轴都是 `-1` 对应 0xFFFF，不是它的标准溢出码。应检查 I²C 应答、供电、器件型号和实际数据，不能只根据有符号数为负判断故障。

项目使用 8 位地址形式 `0x3C`，对应 7 位地址 `0x1E`，读地址为 `0x3D`。正常 ID 字节为 `0x48、0x34、0x33`，即 ASCII `H43`。

QMC5883L 与 HMC5883L 不是同一芯片，不能直接共用地址、寄存器表和换算参数。

### 7.4 地磁计为什么不能照搬静止零偏校准

磁力计静止时应测到当地真实磁场，各轴不应被强制归零。单个静止姿态不能区分“真实地磁分量”和“传感器/安装偏置”。

常见磁场校准包括：

- **硬铁偏置**：固定磁场偏移，常见来源为磁铁、带磁性部件等。
- **软铁畸变**：周围材料改变磁场分布，产生轴间比例和耦合误差。

一般需在多个姿态采样，进行球面或椭球拟合。简化逐轴极值方法为：

```text
轴偏置 ≈ (该轴最大值 + 该轴最小值) / 2
轴半幅 ≈ (该轴最大值 - 该轴最小值) / 2
```

这种方法依赖姿态覆盖，且不能完整修复所有软铁耦合问题。

电机、电调、电池大电流导线会干扰磁力计；随电流变化的干扰不一定能靠一组固定偏置解决。先改善安装位置和布线，再谈校准效果。

### 7.5 磁力计如何得到方向

在特定水平坐标约定下，可以用类似 `atan2(MY, MX)` 的关系估计磁航向；实际符号和轴顺序必须与安装方向、坐标系定义一致。

倾斜时需要倾斜补偿，否则磁场在轴上的投影变化会被误当成航向变化。地理真北与磁北还有磁偏角差异。

因此，**原始 MX、MY、MZ 不能直接当作角度，更不能除以 1090 就得到航向角**。

## 8. 更新频率、读取频率和发送频率

这三个频率不同：

```mermaid
flowchart LR
    A[芯片更新输出数据] --> B[采集任务读取寄存器]
    B --> C[共享数据快照]
    C --> D[通信任务发送]
    D --> E[蓝牙分包与手机显示]
```

| 环节 | 当前源码设置 | 注意事项 |
|---|---|---|
| MPU 采样率分频 | 100 Hz | 不代表应用程序确实取得了 100 个独立完整帧/秒 |
| HMC 连续输出 | 75 Hz | 更快读取可能重复得到同一次测量 |
| AppTaskSensor | 每轮处理后延时 1 ms | 总周期还包括 I²C 读取、抢占和其他处理时间 |
| APPTaskCom | 每轮发送后延时 10 ms | 总周期还包括阻塞发送及抢占 |
| OS tick | 1000 Hz | 是调度时间粒度，不是传感器物理采样率 |
| UART1 | 115200、8N1 | 是通信参数，不是传感器量程或采样频率 |

程序部分注释仍写“每 5 ms”“200 Hz”。当前任务循环已不是固定 5 ms，`tick_counter` 也只是采集函数调用次数，不能直接视为真实毫秒时间。

把 HMC 和 MPU 都设置为每次函数调用读取，只实现了**软件读取次数相同**，没有把 HMC 的 75 Hz 内部输出自动变成 MPU 的采样率，也没有实现两颗芯片严格同步。

角速度积分中的 `dt` 必须来自实际时间戳；不能因为 `OSTimeDlyHMSM(..., 1)` 就假设整个采集周期一定是 1 ms。

> 注：本表是编写本文时核对的源码状态，其中"姿态解算"一项后来已由 `MyLib/Quaternion.c`
> 与 `MyLib/Attitude.c` 补上；其余各项的结论未变。

编写时核对的 `MPU6050_GetData()` 和 `HMC5883L_GetData()` 都是逐寄存器读取，不是整帧连续读取。不能把之前讨论过的连续读取方案当作当前已生效的源码状态。

现有校准仍需注意：

1. 必须水平静止、+Z 朝上；没有自动静止和水平检测。
2. 持续无应答会使首次校准一直等待，尚未设置总超时。
3. 正常采集的有效性传播不完整，读取错误仍可能被发布。
4. 100 次采样不等于恰好 1 秒，还包含读取时间和调度等待。

## 10. 如何看懂手机数据

例如：

```text
MPU A:0,0,2048 G:0,0,164
HMC M:545,0,0
```

按当前配置解释：

```text
A:0,0,2048 → 约 0g、0g、+1g
G:0,0,164 → 约 0、0、+10 °/s
M:545,0,0 → 约 +50、0、0 µT，尚未做磁场校准
```

这里仅为换算示例，不表示静止机体应该有 164 的陀螺仪读数，也不表示当地真实磁场只在 X 轴上。

当前串口发送的是十进制文本，不是这些已经换算好的浮点结果。

## 11. 改量程时的检查清单

1. 修改芯片量程寄存器，并在硬件上读回确认。
2. 同步修改原始值到物理单位的转换系数。
3. 加速度计同步核对 1g 校准基准；本项目宏根据加速度配置自动计算。
4. 在新量程下重新采集偏置，不能直接沿用旧的原始计数偏置。
5. 检查是否发生饱和，是否需要调整滤波和采样率。
6. 检查所有下游算法的单位：g 或 m/s²、°/s 或 rad/s、Gauss 或 µT。
7. HMC 改增益后，要核对磁场转换系数及以原始计数保存的磁场校准参数。

特别注意：**陀螺仪量程和加速度量程互相独立**。只改陀螺仪量程，不会自动改变加速度的 1g 计数；只改加速度量程，也不会自动改变陀螺仪转换系数。
